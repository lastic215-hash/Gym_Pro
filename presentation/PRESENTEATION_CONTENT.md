## الشريحة 2: المقدمة والمشكلة

**العنوان:**(problem Statement) مشكلة البحث

**المحتوى:**

تعاني الصالات الرياضية في ليبيا من一系列 من التحديات في إدارة عملياتها اليومية:

1. **الإدارة اليدوية:** تعتمد معظم الصالات على السجلات الورقية والأدوات اليدوية، مما يؤدي إلى بطء الإجراءات وأخطاء متكررة

2. **فقدان البيانات:** عدم وجود نظام مركزي لتخزين بيانات الأعضاء، مما يسبب فقدان معلومات مهمة عند فقدان السجلات الورقية

3. **صعوبة التتبع:** عدم القدرة على تتبع حضور الأعضاء وحضورهم بشكل فعال ودقيق

4. **التحديات المالية:** صعوبة متابعة الإيرادات والمصروفات وحساب الأرباح بشكل دقيق

5. **تنسيق الأدوار:** عدم وجود نظام واضح لتنسيق الصلاحيات بين المدير وموظفي الاستقبال والمدربين

6. **غياب التقارير:** عدم القدرة على إنتاج تقارير مالية وإدارية دورية لاتخاذ القرارات

**ملاحظة للمصمم:** يمكن عرض كل نقطة مع أيقونة بسيطة. تصميم عناصر card بتأثير ظل خفيف. الألوان: خلفية داكنة، نصوص بيضاء، أيقونات بألوان زاهية.

## الشريحة 4: الحل المقترح والتقنيات

**العنوان:** الحل المقترح والتقنيات المستخدمة

**المحتوى:**

### الحل المقترح
تم تطوير نظام **GYM_Pro** كتطبيق سطح مكتب ذكي يجمع بين قوة تطبيقات سطح المكتب والمرونة على الويب، مع دعم كامل للغة العربية ويعمل في وضع بدون اتصال بالإنترنت.

### التقنيات المستخدمة

**الطبقة الأمامية (Frontend):**
- **Electron 42** - إطار عمل لبناء تطبيقات سطح المكتب
- **Vanilla JavaScript** - البرمجة بدون استخدام أطر عمل جانبية
- **Tailwind CSS** - إطار عمل CSS للتصميم السريع
- **Chart.js** - مكتبة الرسوم البيانية

**الطبقة الخلفية (Backend):**
- **Node.js** - بيئة تشغيل JavaScript
- **Express 5.2** - إطار عمل لبناء واجهات برمجة التطبيقات

**قاعدة البيانات (Database):**
- **MySQL** - نظام إدارة قواعد البيانات العلائقية
- **محلية + سحابية (Railway)** - نظام مزامنة مزدوج

**أدوات إضافية:**
- **PDFKit** - توليد ملفات PDF
- **Arabic Reshaper** - دعم النصوص العربية في PDF
- **Puppeteer** - طباعة وتصدير التقارير

**ملاحظة للمصمم:** تقسيم الشريحة إلى قسمين: الحل المقترح (يسار) والتقنيات (يمين). كل تقنية في badge أو chip ملون. يمكن استخدام ألوان مختلفة لكل فئة تقنية.

## الشريحة 5: هيكل النظام والتصميم المعماري

**العنوان:** هيكل النظام (System Architecture)

**المحتوى:**

### المعمارية العامة

يعمل النظام على مبدأ **العميل-الخادم** مع دعم كامل للعمل بدون اتصال:

```
┌─────────────────────────────────────────────┐
│              تطبيق Electron                  │
│  ┌─────────────────────────────────────┐    │
│  │     الواجهة الأمامية (HTML/JS/CSS)   │    │
│  │  ┌─────────┬──────────┬───────────┐ │    │
│  │  │ المدير  │ الاستقبال│  المدرب   │ │    │
│  │  └─────────┴──────────┴───────────┘ │    │
│  └─────────────────────────────────────┘    │
│                     ↓                       │
│  ┌─────────────────────────────────────┐    │
│  │     الخادم (Express API)            │    │
│  └─────────────────────────────────────┘    │
│                     ↓                       │
│  ┌─────────────────────────────────────┐    │
│  │     SmartPool (مزدوج MySQL)         │    │
│  │  ┌──────────┐    ┌──────────────┐   │    │
│  │  │ محلي     │    │  سحابي      │   │    │
│  │  │ localhost │    │  Railway     │   │    │
│  │  └──────────┘    └──────────────┘   │    │
│  │         ↑                           │    │
│  │  ┌──────────────────────────────┐   │    │
│  │  │  SyncEngine (مزامنة كل 30s)  │   │    │
│  │  └──────────────────────────────┘   │    │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

### مكونات النظام الرئيسية

1. **الواجهة الأمامية:** واجهة عربية كاملة مع دعم RTL وثلاثة لوحات تحكم حسب الدور
2. **الخادم:** واجهة برمجة تطبيقات RESTful مع 35+ مسار API
3. **SmartPool:** فئة ذكية لإدارة اتصالات MySQL المزدوجة (محلي + سحابي)
4. **SyncEngine:** محرك مزامنة خلفية يقوم بنقل البيانات من المحلي إلى السحابة كل 30 ثانية
5. **قاعدة البيانات:** 13 جدول تدعم جميع عمليات النظام

**ملاحظة للمصمم:** رسم المعمارية كمخطط (diagram) احترافي بدل النص العادي. استخدام ألوان مختلفة لكل طبقة. سهم يربط بين المكونات. خلفية شفافة أو gradient خفيف.

## الشريحة 6: تصميم قاعدة البيانات

**العنوان:** تصميم قاعدة البيانات (Database Design)

**المحتوى:**

### الجداول الرئيسية (13 جدول)

| الجدول | الوظيفة |
|--------|---------|
| **members** | بيانات الأعضاء (الاسم، الهاتف، الخطة، المدرب، تاريخ التسجيل، حالة الاشتراك) |
| **plans** | خطط الاشتراك (الاسم، المدة، السعر) |
| **employees** | بيانات الموظفين (الاسم، الدور، كلمة المرور، التخصص) |
| **attendance** | سجل حضور الأعضاء (يُحذف تلقائياً بعد 24 ساعة) |
| **trainer_attendance** | حضور المدربين (مميز: فريد لكل عضو/مدرب/تاريخ) |
| **expenses** | سجل المصروفات (الوصف، المبلغ، الفئة، التاريخ) |
| **audit_logs** | سجل المراجعة (تسجيل كل إجراء في النظام) |
| **payments** | المعاملات المالية (المبلغ، طريقة الدفع، التاريخ) |
| **shift_logs** | سجل نوبات العمل (الإيرادات vs المصروفات الفعلية) |
| **treasury_deposits** | سجل إيداعات الخزينة |
| **employee_workdays** | جدول أيام عمل المدربين |
| **trainer_sessions** | جلسات التدريب |
| **__sync_queue** | طابور المزامنة للعمل بدون اتصال |

### العلاقات الرئيسية
- **member** ←→ **plan** (عضو ينتمي لخطة)
- **member** ←→ **employee** (عضو مُعيَّن لمدرب)
- **attendance** ←→ **member** (سجل حضور لعضو)
- **payment** ←→ **member** + **plan** (دفعة مرتبطة بخطة وعضو)
- **expense** ←→ **employee** (مصروف تم إنشاؤه بواسطة موظف)

**ملاحظة للمصمم:** رسم مخطط العلاقات (ER Diagram) بشكل احترافي. استخدام أشكال ملونة للجداول وخطوط تربط بينها. الجداول الرئيسية بتأثير 3D أو ظل.

## الشريحة 7: الأدوار والصلاحيات

**العنوان:** الأدوار والصلاحيات (Roles & Permissions)

**المحتوى:**

يدعم النظام **ثلاثة أدوار رئيسية** كل منها拥有 واجهة خاصة به:

### 1. المدير (Manager) 🔑
**الصلاحية الكاملة:**
- لوحة تحكم شاملة مع إحصائيات ورسوم بيانية
- إدارة الخطط والاشتراكات (إضافة/تعديل/حذف)
- إدارة الموظفين بالكامل
- التحليلات المالية المتقدمة (إيرادات، مصروفات، أرباح)
- سجل المراجعة الكامل ( Audit Log)
- تحليل ساعات الذروة
- تصدير التقارير (PDF, CSV)

### 2. موظف الاستقبال (Receptionist) 📋
**صلاحيات محدودة:**
- البحث عن الأعضاء وتسجيل الدخول
- تسجيل أعضاء جدد
- قائمة الأعضاء (النشطين والمنتهيين)
- إدارة المالية اليومية (المصروفات، الخزينة)
- طباعة بطاقات الأعضاء والإيصالات

### 3. المدرب (Trainer) 🏋️
**صلاحيات مخصصة:**
- قائمة المتدربين المُعيَّنين له
- تسجيل الحضور اليومي
- سجل الحضور لكل عضو (آخر 50 سجل)
- حالة العمل (يوم عمل / إجازة)

### نظام تسجيل الدخول
- تسجيل دخول بكلمة مرور
- جلسة محفوظة في المتصفح (تُحذف عند إغلاق التطبيق)
- حماية المسارات حسب الدور

**ملاحظة للمصمم:** عرض كل دور في عمود مع لون مميز وتأثير border. أيقونة لكل دور. عرض الصلاحيات كقائمة points. يمكن استخدام مخطط شجري.

## الشريحة 8: الميزات الرئيسية

**العنوان:** الميزات الرئيسية (Key Features)

**المحتوى:**

### إدارة الأعضاء 👥
- تسجيل أعضاء جدد مع اختيار الخطة والمدرب
- تسجيل + دفع في معاملة واحدة ( TRANSACTIONAL)
- بحث ذكي بالاسم أو الهاتف (بتأخير 300ms)
- نظام تسجيل دخول مع التحقق من صلاحية الاشتراك
- تجديد الاشتراك مع معالجة الدفع
- اشتراكات تنتهي تلقائياً كل ساعة

### الإدارة المالية 💰
- تتبع الإيرادات مقابل المصروفات
- فئات المصروفات (إيجار، مرافق، رواتب، تسويق، معدات)
- تسوية يومية للنقود (نقد/بطاقة)
- نظام إيداع الخزينة (إيداع واحد يومياً)
- ملخص مالي شهري
- تصدير CSV وطباعة التقارير

### التحليلات والتقارير 📊
- تحليل ساعات الذروة (رسم بياني شريطي)
- توزيع الإيرادات حسب النشاط (رسم بياني دائري)
- رسم بياني لاتجاه الإيرادات والمصروفات (6 أشهر)
- طباعة بطاقات الأعضاء
- طباعة الإيصالات

### النظام السحابي ☁️
- عمل النظام بدون إنترنت (Offline-First)
- مزامنة تلقائية كل 30 ثانية
- فحص صحة الاتصال كل 15 ثانية
- مؤشر حالة الاتصال (أخضر/برتقالي/أحمر)
- إعادة الاتصال التلقائية عند عودة الإنترنت

### الأمان والمراجعة 🔒
- تسجيل كل إجراء في النظام (Audit Log)
- فلترة السجلات حسب الدور والمستخدم والتاريخ
- حماية المسارات حسب دور المستخدم

**ملاحظة للمصمم:** عرض الميزات في بطاقات (cards) بتصميم grid. كل ميزة مع أيقونة وعنوان فرعي ونقاط. تأثير hover خفيف. يمكن تقسيمها إلى صفوف.

## الشريحة 9: واجهة برمجة التطبيقات (API)

**العنوان:** واجهة برمجة التطبيقات (API Design)

**المحتوى:**

### إحصائيات النظام
| المقياس | العدد |
|---------|-------|
| مسارات API | **+35 مسار** |
| جداول قاعدة البيانات | **13 جدول** |
| أسطر الكود | **~5,800 سطر** |
| ملفات المصدر | **18 ملف** |
| أدوار المستخدمين | **3 أدوار** |

### هيكل المسارات

**المصادقة:**
- `POST /api/auth/login` - تسجيل دخول الموظف

**الأعضاء:**
- `POST /api/checkin` - تسجيل دخول العضو
- `GET /api/members/search` - بحث ذكي
- `POST /api/members/register` - تسجيل عضو جديد
- `POST /api/members/register-and-pay` - تسجيل + دفع
- `PUT /api/members/:id` - تعديل بيانات العضو
- `DELETE /api/members/:id` - حذف العضو
- `POST /api/members/renew` - تجديد الاشتراك

**الموظفين:**
- `POST /api/employee/clock-in` - تسجيل حضور/انصراف
- `POST /api/employee/attendance/mark` - تسجيل حضور المتدرب

**المدير:**
- `GET /api/manager/dashboard-stats` - إحصائيات لوحة التحكم
- `GET /api/manager/analytics/peak-hours` - تحليل ساعات الذروة
- `GET /api/manager/analytics/revenue-spread` - توزيع الإيرادات
- `POST /api/manager/employees` - إضافة موظف
- `POST /api/manager/plans` - إضافة خطة
- `POST /api/manager/expenses` - إضافة مصروف
- `GET /api/manager/audit-logs` - سجل المراجعة

**المالية:**
- `GET /api/shift/financial-summary` - ملخص مالي يومي
- `POST /api/shift/reconcile-and-deposit` - تسوية الخزينة
- `GET /api/shift/monthly-summary` - ملخص شهري

### مبادئ التصميم
- **RESTful**: معمارية REST مع استخدام صحيح ل METHODS
- **Transactable**: المعاملات المالية تستخدم Transaction
- **Role-based**: حماية المسارات حسب دور المستخدم
- **Arabic-first**: كامل الاستجابة باللغة العربية

**ملاحظة للمصمم:** عرض الإحصائيات في أرقام كبيرة (KPI style) في الأعلى. المسارات في جدول أو قائمة منظمة. يمكن عرض مبدأ التصميم في نقاط.

### التوصيات Recommendations

**لتحسين النظام مستقبلاً:**

1. **تشفير كلمات المرور:** استخدام bcrypt لتشفير كلمات المرور في قاعدة البيانات بدلاً من النص العادي لتحسين الأمان

2. **نظام المصادقة المتقدم:** تطبيق JWT مع httpOnly cookies بدلاً من الجلسات المحفوظة في المتصفح

3. **التحقق من المدخلات:** إضافة middleware للتحقق من صحة جميع البيانات المدخلة لمنع الهجمات

4. **نظام الاختبارات:** إنشاء اختبارات تكاملية (Integration Tests) لضمان جودة النظام

5. **تحسين الأداء:** إضافة pagination للقوائم الكبيرة بدلاً من تحميل جميع البيانات دفعة واحدة

6. **نسخ احتياطي تلقائي:** إنشاء نظام نسخ احتياطي تلقائي لقاعدة البيانات

7. **تطبيق موبايل:** تطوير تطبيق موبايل إضافي للأعضاء لمتابعة حضورهم واشتراكاتهم

8. **نظام الإشعارات:** إضافة نظام إشعارات للتنبيه على انتهاء الاشتراكات والأحداث المهمة

9. **تحسين واجهة المستخدم:** إضافة dark mode وتحسين تجربة المستخدم على الشاشات الصغيرة

10. **التوسع الجغرافي:** دعم العملات والألوان المختلفة لإمكانية التوسع لدول أخرى

**ملاحظة للمصمم:** الشريحة الأخيرة مقسمة إلى قسمين: النتائج (يسار) والتوصيات (يمين). النتائج في نقاط مختصرة. التوصيات في قائمة مرقمة. في الأسفل: "شكراً" بخط كبير وبيانات التواصل. خلفية gradient خاص.

---

## ملاحظات عامة للمصمم

### الهوية البصرية
- **اللون الأساسي:** كحلي غامق (#0f172a) للخلفيات
- **اللون الثانوي:** أزرق كهربائي (#3b82f6) للعناصر الرئيسية
- **اللون المساعد:** أخضر (#10b981) للنجاح والإيجابي
- **لون التحذير:** برتقالي (#f59e0b) للتنبيهات
- **النص:** أبيض (#f8fafc) على خلفيات داكنة

### الخطوط
- **العنوانات:** خط Tajawal (Bold أو Black)
- **النصوص:** خط Tajawal (Regular أو Light)
- **الأرقام الإحصائية:** يمكن استخدام خط Orbitron (科技感)

### الانتقالات
- انتقال سلس بين الشرائح (fade أو slide)
- تأثير ظهور تدريجي للمحتوى (staggered animation)
- شريط تقدم في الأسفل يوضح الموقع الحالي

### الحجم
- حجم الخط الرئيسي: 28-32px للعناوين
- حجم الخط الفرعي: 18-22px للنصوص
- حجم الخط الصغير: 14-16px للملاحظات

### التخطيط
- كل شريحة ملء الشاشة بالكامل
- مساحة كافية حول المحتوى (padding)
- عدم إزدحام الشرائح بالمحتوى
- استخدام البطاقات (cards) لتنظيم المعلومات
